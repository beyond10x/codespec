# Story: Rust reader: conditional compilation and parameter shadowing

## Outcome

Someone who reads a Rust crate with `codespec-read-rust` and writes it as Go gets the behaviour of a
normal build of that crate: test-only code is left out, code under a condition the reader cannot
resolve is refused instead of guessed, and a function that shadows its parameter writes Go that
builds and returns what the Rust returns.

## Findings

- A4 (the reader read `#[cfg(test)]` statements as production code): `files` now applies
  conditional compilation to every item before it is read (`built`, `Prune`): a module, item,
  statement, match arm, struct literal field, impl or trait item, field or variant under
  `cfg(test)` (or `all(test, …)`) is left out; what `not(test)` marks is read. A statement under a
  condition the reader cannot resolve (a feature, a platform, `debug_assertions`) is `foreign` with
  a refusal; an item under one, or holding another part under one, is refused, a function or impl
  among them opaque with its calls.
  Tests: `adapters/rust-read/tests/reader.rs::code_built_only_for_tests_is_not_read`,
  `adapters/rust-read/tests/reader.rs::test_only_statements_leave_the_written_go_returning_the_normal_builds_value`,
  `adapters/rust-read/tests/reader.rs::code_under_a_condition_the_reader_cannot_resolve_is_refused`.
- A5 (a `let` shadowing a parameter wrote `n := n + 5` in the parameter's scope): a function's
  and a closure's outermost block now share the parameters' scope, as Go's do, so the shadow gets a
  fresh name.
  Tests: `adapters/rust-read/tests/reader.rs::a_let_that_shadows_a_parameter_binds_a_new_name`,
  `adapters/rust-read/tests/reader.rs::a_shadowed_parameter_writes_go_that_builds_and_returns_the_rust_value`.

## Done When

- The five tests above pass and failed before the fix.
- `cargo test -p codespec-read-rust`, `task examples-inventory` and `task examples-series` are
  green, with checked-in outputs regenerated by their tasks where they changed.
