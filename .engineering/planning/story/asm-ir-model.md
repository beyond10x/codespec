# Story: The `asm_ir/1` model: types, strict reading, canonical JSON, schema, builder

## Outcome

`crates/asm-ir` (`b10x-codespec-asm-ir`) is the only definition of `asm_ir/1`, as
`crates/model` is of `cir/1`: the Rust types of `docs/asm-ir.md` §§ 3 and 4, strict reading
(`Module::from_json`), canonical JSON (`to_json`), the JSON Schema `schemas/asm-ir-1.schema.json`
generated by `codespec schema --asm-ir` and drift-checked, a `Builder` that the lowering and the
tests use to make functions block by block, and a text printer (`v3`, `slot0`, `b2`) for humans.

It also registers the epic's other three crates as skeletons, so every later story of the epic
touches only its own directory.

## Done When

- A failing test first: `reads_back_what_it_writes` builds `func add(i64, i64) -> i64` with the
  builder, writes it, reads it, and gets the same bytes; it fails until the crate exists.
- Strict reading refuses, each with a test naming the defect: another `format`; `word` other than
  64; an unknown field or node kind; a vreg, slot, block or symbol that does not exist; an operand
  of the wrong type for its instruction's `t`; an immediate out of range of its type, or not a
  canonical decimal string (A9: `"007"`, `"+1"`, `"1e3"` refused); a block without a terminator;
  block 0 as a jump target; a `call` whose arguments or results disagree with the callee; a `ret`
  that disagrees with `results`; a `syscall` outside `write read exit mmap` or of the wrong arity;
  a `features` list that does not match use; a name with a control or format character; two
  objects of one name; an `entry` with parameters or results.
- A forward check refuses a vreg read on a path where it was not assigned, naming the function,
  block and vreg.
- `schemas/asm-ir-1.schema.json` is generated and `cargo test -p b10x-codespec-asm-ir` fails when
  it drifts from the types.
- The printer's output for the `add` module is checked in as a test fixture.
- `cargo build --workspace --locked` builds the skeleton crates `crates/lower`, `adapters/asm` and
  `adapters/asm-run` (a crate doc and an empty library or `main` each, with the dependency list of
  the design), and `task check-parts` passes with their `test` parts listed.
- Every test under 60 s; the crate's test step under 120 s; one integration-test binary
  (`tests/main.rs`).

## Scope

- Own: `crates/asm-ir` (new), `schemas/asm-ir-1.schema.json` (new), `crates/cli` (`codespec
  schema --asm-ir`), the skeletons `crates/lower`, `adapters/asm`, `adapters/asm-run` (new), root
  `Cargo.toml` `members` (all four), `Cargo.lock`, `scripts/check-parts.txt` (the four `test`
  parts), `AGENTS.md` (the four crate rows and the generated-file row).
- No other story of the epic writes root `Cargo.toml` `members`, `scripts/check-parts.txt` or the
  crate table of `AGENTS.md`; a later story that needs a dependency adds it to its own crate's
  `Cargo.toml` and its edges to `Cargo.lock`.
