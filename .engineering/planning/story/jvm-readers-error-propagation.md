# Story: The Java reader claims error propagation, and the ledger throws again

## Outcome

`codespec-read-java` claims `sem.error.propagate`: the kit case has a Java source (a method that
calls a method throwing a sentinel exception and does not catch it), and `examples/ledger` gets
back the throwing call it was reshaped to avoid.

## Context

The Java reader already lifts a call of a throwing method, as a statement or a local initializer,
into the propagation form (`adapters/java/src/codespec/read/Reader.java`, `throwingCallee` and
`propagate`); a throwing `void` method becomes the error-only form `err := a.Post(…); if err != nil
{ return …, err }`. `examples/ledger` was reshaped so that `Account.post` does not throw, because
the Rust writer refused a call of a fallible function (story java-example-ledger).
`story:rust-writer-error-propagation` writes both the value-returning and the error-only form with
`?`.

The Groovy reader is out: it has no exception model (epic errors-cross-every-adapter, Out of
Scope).

## Acceptance

- `conformance/cases/sem-error-propagate/java/Case.java` holds the case in Java; `ReaderTest` reads
  it with no refusal and no `foreign`, and its Go run equals `expected.txt`.
- The Java reader's claim list names `sem.error.propagate`; `website/data/conformance/reader-java.json`
  lists it claimed and `pass`.
- The Groovy corpus takes `java/Case.java` as its fallback, and the Groovy reader refuses `throw`,
  so `reader-groovy.json` gains a `sem.error.propagate` row `refused` with the case (unclaimed, as
  `expr.errvar` is), still `conforms: true`; `adapters/groovy/README.md` lists the id among the
  refused, unclaimed features.
- `examples/ledger/source`: the overdraft check (`kind == WITHDRAWAL && balance < amount`, throwing
  `InsufficientFunds`) moves from `Ledger.post` into `Account.post`, which declares `throws
  LedgerException`; `Ledger.post` calls `a.post(kind, amount)` without catching.
- `codespec read --lang java examples/ledger/source` gives `ledger.read.cir.json` with no refusal,
  and the call of `Account.post` in `Ledger.post` is the error-only propagation form.
- `examples/ledger/out/go` and `out/rust` are regenerated with no refusal, and both build.
- `task examples-ledger` is byte-equal over 200 seeds of 300 commands across the original Java,
  the Go and the Rust.
- At least one harness trace posts an overdrawing withdrawal and prints `InsufficientFunds`'s
  message (shown by a command in the trace output the harness compares).
- `examples/fees` outputs are byte-unchanged.

## Scope

- `adapters/java/src/codespec/read/Main.java` (the claim list); `Reader.java` only if the form is
  not already read as described.
- `adapters/java/README.md` (the case table); `adapters/groovy/README.md` (the refused, unclaimed list
  only).
- `conformance/cases/sem-error-propagate/java/Case.java`.
- `examples/ledger/**` (source, read, outputs, drivers if the trace format needs the error).
- `CHANGELOG.md`: one entry (shared with `story:rust-reader-error-propagation`; the second merge
  keeps both entries).
- Regenerated by `task docs-generate`, never hand-edited: `conformance/reader/java/`,
  `conformance/reader/groovy/` (the Groovy corpus takes `java/Case.java` as its fallback source, so
  check whether the Groovy reader's report changes), all six `website/data/conformance/*.json`,
  `website/data/support-matrix.json`. Shared with `story:rust-reader-error-propagation`: when both
  are in one wave, the second merge takes either side of those generated files and `task
  docs-generate` runs on the merged head.
