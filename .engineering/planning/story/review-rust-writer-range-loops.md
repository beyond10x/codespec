## Outcome

A `for … range` written by `codespec-write-rust` computes what Go computes when its body changes
the source. A slice loop whose body rebinds the slice variable reads the storage the loop started
with (a copy made when the loop starts) instead of indexing the rebound variable and panicking. A
map loop whose body writes entries reads each value when its iteration reaches the key, from a
snapshot of the keys, instead of iterating a stale copy of the map. A body that both rebinds its
source and writes an element of it, or calls what can reach the source's storage, is refused
with a reason naming it: neither the variable nor a copy holds what Go reads.

## Findings

- A3 (Rust slice iteration panics after the source variable is rebound):
  `adapters/rust/tests/writer.rs::a_slice_loop_reads_the_slice_it_started_with_after_its_variable_is_rebound`
  and `adapters/rust/tests/writer.rs::a_slice_loop_that_writes_an_element_and_rebinds_its_variable_is_refused`.
- A6 (Rust map iteration uses stale values):
  `adapters/rust/tests/writer.rs::a_map_loop_reads_each_value_as_the_earlier_iterations_left_it`.
