# Story: Readers report the byte span of every function, beside the cir/1 document

## Outcome

`codespec read --spans <file>` writes, beside the `cir/1` document and not inside it, two kinds of
record per source file. One per function definition (a function with a body): module, function
name (and receiver), source file, and the byte offsets of its first and last byte. One per file
for its import block: the byte offsets of the file's import, `use` or `#include` lines as one
range, or the offset where one would be inserted when the file has none. A declaration without a
body (a Go function implemented elsewhere, a C prototype, a trait method without a default) gets
no record. The Go, Rust and C readers give the file; a reader that does not is named in it as
giving none. `cir/1` is unchanged.

## Acceptance

- `docs/design.md` describes the span file (its format name and fields) and says that it is not
  part of `cir/1`.
- For each of Go, Rust and C, a test over a checked-in example checks for every function
  definition that its span starts at the first byte of its doc comment, or of its first attribute
  or annotation, or of its declaration when it has neither, and ends at its closing brace; that
  cutting every span out of the file leaves no part of any function body; and that a declaration
  without a body has no record.
- Named cases with their expected spans checked in: two functions on one line (two spans that do
  not overlap, the first ending at its brace, the second starting at its first byte); a method; a
  function with attributes or annotations before it (inside the span); a file with CRLF line ends
  (offsets count both bytes); a file with a byte-order mark (its three bytes count in every
  offset, and the first function's span does not include them); a multi-byte character before a
  function (offsets are bytes, not characters). A function inside a macro or generated by one
  gets no span, and the file names it with the reason.
- The import range of a file with imports covers those lines and nothing of a function; a file
  with none gives an insertion offset after the package or module header; one case each per
  language.
- Reading with and without `--spans` gives byte-identical `cir/1` documents.
- A Java read with `--spans` writes a file that says the reader gives no spans.

- Own: `adapters/go/cmd/codespec-read-go`, `adapters/rust-read`, `adapters/c-read`, `crates/cli`

  `crates/mcp`.
- Runs after `story:mcp-server-read-tools`: both edit `crates/cli` and `CHANGELOG.md`, and that
  is the only reason for the order. It can be worked beside `story:mcp-semantic-tools` and

  which edit the same adapters.
