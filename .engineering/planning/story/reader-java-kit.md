# Story: The Java reader claims the remaining kit features

## Outcome

`codespec-read-java` claims and passes the kit features it can read and does not claim today
(77 of 120 verified), each through a `conformance/cases/<case>/java/Case.java` that the Java
runner runs to the case's `expected.txt`. The 43 open ones are the features with verdict
`untested` in `website/data/conformance/reader-java.json` less the seven `fact.*`.

## Acceptance

- The Java `read` column has at least 100 of 120 `verified`; `reader-java.json` has `fail` 0
  and `conforms: true`.
- Each of the 43 still unclaimed is named in `adapters/java/README.md` with its reason: no Java
  source form (name the construct, for example `&^`), not runnable at step 4 (the three extern
  features), or the reason found. At most 20 stay unclaimed. The 9 the README names as having no Java form stay unclaimed. The 7 it
  refuses by design today (`assign.shl`, `assign.shr`, `op.shl`, `op.shr`, `expr.to_error`,
  `intrinsic.errorf`, `sem.switch.break`) are mapped, or the README states per feature what in
  `cir/1` or the reader check prevents it.
- `decl.union`: the case source is added here; `story:reader-check-evaluator-step` claims it
  later. `stmt.foreign` stays unclaimed.
- Groovy guard: `website/data/conformance/reader-groovy.json` still has `conforms: true` and
  loses no `pass`. A new `java/Case.java` that Groovy 2.4 compiles to another meaning gets its
  own `groovy/Case.groovy`; one the Groovy reader refuses stays unclaimed by Groovy.
- Every feature claimed before is still `pass`; `task conformance`, `task adapters-check`,
  `task examples` exit 0.

## Scope

- Own: `adapters/java`, `adapters/jvm`, `conformance/cases/*/java/`,
  `conformance/cases/*/groovy/` only for the guard above; `examples/ledger/**` and
  `examples/fees/**` through `task examples` where the reader's output changes. Inferred.
- Shared with the unit in the other slot, resolved by the coordinator at merge: `CHANGELOG.md`
  (each adds its own entry), `AGENTS.md` (its own rows), `Taskfile.yml` (its own steps),
  `conformance/cases/<case>/` (a unit adds only files of its own language to an existing case and
  never edits its `case.cir.json`, `calls.json`, `expected.txt`, `features.json` or `case.go`).
- A unit may add a variant case directory (`crates/conformance/src/lib.rs` § `features.json`: a
  second case of a subject in a form the language can write), built with `task conformance`, and
  names each one in its report. Counts of cases are read on the merged head.
- Regenerated by the coordinator on the merged head, never committed by a unit:
  `conformance/reader/<lang>/**`, `website/data/conformance/*.json`,
  `website/data/support-matrix.json`, `website/data/status.json` (`task docs-generate`);
  `examples/*/*.cir.json`, `examples/*/out/**`, `examples/netcheck/*`,
  `website/docs/examples/*.md` (`task examples`, `task examples-netcheck`);
  `adapters/groovy/testdata/lending.read.cir.json` where a JVM change rewrites it.
- `cir/1` does not change. A feature that needs a change of `crates/model` is reported and left
  unclaimed.
- The measure is the count of features with state `verified` in the reader's `read` column of
  `website/data/support-matrix.json`, of the 120 a reader can claim: the 127 of `kit.json` less
  the seven `fact.*`, which `crates/model/src/manifest.rs` refuses in a reader manifest.
