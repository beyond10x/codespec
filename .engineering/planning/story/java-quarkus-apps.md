# Story: Read Java projects and Quarkus applications

## Outcome

`codespec-read-java` (`adapters/java`) reads a project directory as well as a package directory.

- **Project:** a directory with `pom.xml` or `build.gradle(.kts)`. Every package under
  `src/main/java` is read, one `cir/1` module per package, in one `javac` analysis, with the
  dependency jars on the class path. The class path comes from `CODESPEC_JAVA_CLASSPATH` (jars
  separated by `:`), as `CODESPEC_GROOVY_CLASSPATH` does for the Groovy reader. A documented
  `codespec` command or Taskfile recipe produces it with `mvn dependency:build-classpath`. The
  reader itself never runs Maven or Gradle.
- **Dependency calls:** a call into a jar becomes an extern with its declared signature, as the C
  reader does for libc. Code in jars is not read.
- **Quarkus 3:** the reader recognises these annotations and records them in `cir/1`. It uses an
  existing field where one fits (entry points, externs, effects). Otherwise it uses an additive
  `cir/1` field, documented in the model and schema.
  - `jakarta.ws.rs` `@Path` with `@GET`, `@POST`, `@PUT`, `@DELETE` or `@PATCH`: an HTTP entry
    point with its method and joined path.
  - `@ApplicationScoped`, `@Singleton`, `@RequestScoped` and `@Dependent`: a bean.
  - `@Inject` on a field, constructor or parameter: resolved to the one bean that implements the
    type in the read packages, or to an extern when there are none or several.
  - `io.quarkus.scheduler.Scheduled` and `org.eclipse.microprofile.reactive.messaging.Incoming`:
    entry points.
  - `@RegisterRestClient` interfaces: externs with the effect `net`.
  - Panache (`PanacheEntity`, `PanacheRepository`), `EntityManager` and JDBC calls: externs with
    the effect `db`.
- A construct the reader cannot map stays `foreign` with one refusal at its line, as today.

## Acceptance

- The existing behaviour on a package directory is unchanged. `task adapters-check` and the
  `reader-java.json` conformance report are unchanged except for features this story adds.
- A test project under `adapters/java/testdata/quarkus/` builds with `mvn -o -q package` from the
  local Maven repository. Its read is checked in as `adapters/java/testdata/quarkus.read.cir.json`
  and is byte-equal on two reads. It has:
  - one resource with 2 HTTP methods
  - one service bean injected into it
  - one Panache entity
  - one REST client interface
  - one `@Scheduled` method
- `codespec effects` over that read gives the resource method that persists through Panache the
  effect `db` and the one that calls the REST client the effect `net`.
- One application from `github.com/quarkusio/quarkus-quickstarts`, pinned to a commit and named in
  the README, is read with its Maven class path. The README records:
  - the number of modules, functions and refusals
  - the refusals grouped by reason
  - the command that reproduces the read
- `adapters/java/README.md` and `website/docs` describe project reads, `CODESPEC_JAVA_CLASSPATH` and
  the Quarkus mapping, in the installed `codespec` binary's terms.
- `task check` green.

## Constraints

- No Python, anywhere: not in the reader, the tests, fixtures, generators or helper scripts. Use
  Java, Rust, shell or Taskfile recipes.
- The reader stays on the JDK plus the project's own jars: no new dependency of the reader itself.
- `javac --release 17`, `-Xlint:all -Werror`, as the `adapters` task builds it today.

## Out of Scope

- Spring, Micronaut and other frameworks.
- Running Quarkus or its build-time code generation.
- `src/test/java`.
