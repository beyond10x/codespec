# Story: The C reader reads the runtime forms of strings, slices, maps and errors

## Outcome

C has no string value, slice, map, error value, tuple or channel. `codespec-write-c` writes each
through its runtime header (`cs_string`, `cs_slice`, `cs_map`, `cs_any`, ...).
`codespec-read-c` reads those forms back, and only those, so it claims the kit features that
need them. Candidates, 30: `sem.multi_assign.order` (the writer's temporaries), `decl.var`, `decl.union`, `op.eq`, `intrinsic.println`,
`intrinsic.sprintf`, `sem.int.wrap`, `sem.switch.break`, `type.slice`, `type.map`,
`type.error`, `type.any`, `type.tuple`, `type.chan`, `decl.embedded`, `expr.make`,
`expr.method`, `expr.to_error`, `expr.errvar`, `expr.intrinsic`, `intrinsic.append`,
`intrinsic.len`, `intrinsic.errorf`, `intrinsic.sorted_keys`, `sem.error.propagate`,
`sem.map.order`, `stmt.for_range`, `stmt.lookup_else`, `stmt.send`, `unop.recv`.

Not candidates, left unclaimed with the reason in the crate doc: the 8 features
`codespec-write-c` refuses (`decl.interface`, `decl.type_params`, `expr.iface_call`,
`expr.instantiate`, `expr.lambda`, `expr.spread`, `expr.to_iface`, `type.param`:
`story:c-interfaces-generics-closures`) and the three extern features `expr.extern`, `expr.extern_method`, `type.extern`.

## Acceptance

- The crate doc of `adapters/c-read` replaces the rule "the reader resolves no name and infers
  no type of its own" by a stated one: which runtime names it recognises, and where the element
  and key types of `cs_slice`, `cs_map` and `cs_any` come from (a cast at the use, or the
  writer's `/* codespec: type */` lines). A source that uses a runtime name outside the stated
  forms is refused, never guessed; one near-miss test per recognised form holds it.
- A `case.c` in runtime form carries the writer's `/* codespec: type */` and `/* codespec: func */`
  lines. The reader and `codespec-run-c`'s hand-written mode both read the element, key and
  signature types from them, so there is one source of types; a case without them is refused by
  both.
- The runtime header is in the kit: `conformance/c/codespec_rt.h`, with a test that it equals
  `adapters/c/src/codespec_rt.h`. The `c` row of `reader_corpus` writes it beside `case.c`;
  `task docs-check` holds the corpus.
- The C `read` column has at least 100 of 120 `verified`; `reader-c.json` has `fail` 0 and
  `conforms: true`. Each candidate not claimed is named in the crate doc with its reason.
- Round trip, on the merged head: for every kit case `codespec-write-c` writes without refusal,
  `codespec-read-c` reads the output either with no `foreign` statement or with a refusal; a
  `Taskfile.yml` step prints both counts, and the first is at least 100.
- Every feature claimed before is still `pass`; `task conformance` and `task adapters-check`
  exit 0.

## Scope

- Own: `adapters/c-read`, `adapters/c-run` (hand-written mode), `conformance/cases/*/c/`,
  the `c` row of `reader_corpus` in `crates/conformance/src/conform.rs`. Inferred. Runs after
  `story:reader-c-kit-plain` in the same slot; `story:reader-check-evaluator-step` runs after it. Reads but does not edit
  `adapters/c`.
- Shared with the unit in the other slot, resolved by the coordinator at merge: `CHANGELOG.md`
  (each adds its own entry), `AGENTS.md` (its own rows), `Taskfile.yml` (its own steps),
  `conformance/cases/<case>/` (a unit adds only files of its own language to an existing case and
  never edits its `case.cir.json`, `calls.json`, `expected.txt`, `features.json` or `case.go`).
- A unit may add a variant case directory (`crates/conformance/src/lib.rs` § `features.json`: a
  second case of a subject in a form the language can write), built with `task conformance`, and
  names each one in its report. Counts of cases are read on the merged head.
- Regenerated by the coordinator on the merged head, never committed by a unit:
  `conformance/reader/<lang>/**`, `website/data/conformance/*.json`,
  `website/data/support-matrix.json`, `website/data/status.json` (`task docs-generate`);
  `examples/*/*.cir.json`, `examples/*/out/**`, `examples/netcheck/*`,
  `website/docs/examples/*.md` (`task examples`, `task examples-netcheck`);
  `adapters/groovy/testdata/lending.read.cir.json` where a JVM change rewrites it.
- `cir/1` does not change. A feature that needs a change of `crates/model` is reported and left
  unclaimed.
- The measure is the count of features with state `verified` in the reader's `read` column of
  `website/data/support-matrix.json`, of the 120 a reader can claim: the 127 of `kit.json` less
  the seven `fact.*`, which `crates/model/src/manifest.rs` refuses in a reader manifest.
