Covers commit `7eda910` plus the one test file I added. `git --no-pager diff --stat` is empty; `git status` shows only `?? adapters/c-read/tests/adversary1.rs`, a test file, so no implementation file was touched.
Tests added: `adapters/c-read/tests/adversary1.rs`, 5 tests. Each was run alone with `cargo test -p codespec-read-c --test adversary1 -- --exact <name>`, all exit 101, red for the reason given above.
Suite, run after the tests existed: `cargo test --no-fail-fast -p codespec-read-c -p codespec-run-c` exit 101. Tests executed went from 24 to 29 with 5 red (cases 3, reader 12, run-c unit 3, acceptance 6, adversary1 0/5).
Previously refused constructs are all still refused: pointer `++ -- += -=`, `p - q`, `*(p+1)`, `p[i]`, `1[p]`, `p < q`, `if (p)`, `!p`, `f == g`, int↔pointer casts, `sizeof`, comparison used as an int, `void *`, variadic and unprototyped function pointers, VLAs, `long double`, float↔int casts, FloatingCast.
Read correctly, C output equal to Go output: struct copies containing arrays, `&a[i]`, `->` writes, function pointers in struct fields and compared with 0, `{0}` with pointer, float and array fields, f32 literals at 9 digits, `0.30000000000000004`.
expr-zero-struct and expr-nil-ptr `case.cir.json`: validate passes, and the Go, C and Rust writers with their runners each print `expected.txt`. I did not run the JVM writers.
The stated reason for leaving `expr.index` unclaimed is true: the C and Rust writers claim `expr.*` and list `type.array` as not claimed.
Hostile input (unbalanced or odd types, pointer-to-array, function pointer returning function pointer, a file clang rejects) never panicked; a file clang rejects exits 1 with clang's message. Two refusal reasons are misleading: `long (*)[3]` is called "the function pointer type", and a self-referencing `struct S *next` is reported as "struct S, which the source directory does not declare".
Runner: new types are only declared and never printed. A call that passes or returns a float, pointer or function pointer exits 2 naming the type, and a newtype over an integer prints as an integer.
