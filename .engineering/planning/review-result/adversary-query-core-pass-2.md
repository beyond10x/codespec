I found 11 problems in commit `f11b77a`: one major, seven minor, three notes. 12 new tests fail, one per finding (two each for F1 and F2); F10 and F11 have no test.

1. Diff: `git status` shows only two new untracked files, `crates/query/tests/adversary2.rs` (10 cases, 7 red) and `crates/cli/tests/query_adversary2.rs` (5 cases, 5 red). `git diff --stat` is empty, so no implementation file was touched.
2. Each new file was run alone before the suite, exit 101 both times. Its red lines are quoted above as `adversary2::…` and `query_adversary2::…`.
3. Then I ran `cargo test -p b10x-codespec-query -p b10x-codespec-cli --no-fail-fast` (exit 101). 102 tests ran and 13 failed: my 12 red cases plus one existing test, `trace.rs::trace_lists_both_candidates_…`. Its failure is unrelated: two tests in `trace.rs` share `target/tmp/trace/t.cir.json`, and run again alone it passes (2 of 2). Before my additions the suite ran 87 tests (102 minus my 15).
4. Origin: F5, F8 and F9 have the same code at `8bee424`. I read that code with `git show`; I did not run the base.
5. What held:
   - Negation and aggregates: double and triple negation, a relation with both a definite and a possible derivation, a possible fact joined with a definite one, and a negation inside an aggregate, all on both fixtures.
   - `scc` matches my hand-computed answer on a graph with two cycles and a self-loop.
   - The regex matcher matches a 37-row hand-written table (anchors, lazy quantifiers, classes, `{0}`, `{1000}`, `(a*)*`, Unicode by character). It refuses `{1001}`, 101000 instructions and exactly 100000 plus the match instruction.
6. Also held:
   - `dropped-error.cq` agrees with `codespec check` on two wrappers, recursion, mutual recursion and parameters passed crosswise.
   - `int-from-text.cq` agrees on a copy of a copy, a field of a field and a copy into a field of a field.
   - Cache: separate files with and without `--summaries` or `--barrier`, and a changed summary file gives a new result.
7. Regression: the pass-1 tests in `adversary1.rs` (digest vectors, node ids, byte-equal builds) still pass in the suite run.

Outside the worktree I wrote only under `/home/timo/.cache/scratch/2db1a4b7-2d2d-4a62-bab2-d71ac128826e/cs/query-core/adv2/`: logs, probe documents and queries with their `.cq` caches, a Go probe module under `go/`, and the Python generators `gen.py`, `mk2.py` and `mkscc.py`.
