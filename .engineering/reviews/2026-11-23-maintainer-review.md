# CodeSpec 0.10.0 maintainer review

**35 findings across security (3), performance (4) and logic (28).** Twenty-four behavioral findings were reproduced, four performance findings were measured, and seven were verified from source. The closing pass in each area added zero findings.

The Go writer can drop startup code, the C writer can store into the wrong element, and the Rust writer can turn a valid loop into a panic. For teams using CodeSpec to review other repositories, the query engine can also accept cached facts supplied by the repository under review.

Reviewed on 2026-11-23. Both remote `main` and the release tag pointed to `91086c62d676`. [Reviewed source](https://github.com/beyond10x/codespec/tree/91086c62d67611808206a935e8e5857e94cdc0e6)

## Ten priorities

- **Q1 · Query results can come from an input-controlled cache.** *Security · source inspection.* `codespec query` accepts a fact cache beside the first input document before validating the modules or deriving their facts. The digest identifies the inputs, while a separate file supplies the facts. A repository-supplied cache can change review results. Store reusable facts in a reviewer-controlled location and verify that an input-local cache cannot change the answer. [crates/query/src/lib.rs:315](https://github.com/beyond10x/codespec/blob/91086c62d67611808206a935e8e5857e94cdc0e6/crates/query/src/lib.rs#L315) · [crates/query/src/facts.rs:2638](https://github.com/beyond10x/codespec/blob/91086c62d67611808206a935e8e5857e94cdc0e6/crates/query/src/facts.rs#L2638)

- **A1 · Go output loses package initializers.** *Logic · observed.* Two legal `init()` functions added 1 and 2 to the same global. Native Go returned `3`. The reader kept both functions, but generated Go returned `2` because the writer stores both under the same declaration key. Track each `init` occurrence in the writer’s declaration index and emit them in source order. [adapters/go/cmd/codespec-write-go/write.go:335](https://github.com/beyond10x/codespec/blob/91086c62d67611808206a935e8e5857e94cdc0e6/adapters/go/cmd/codespec-write-go/write.go#L335)

- **A2 · C stores a multiple assignment into the wrong element.** *Logic · observed.* With `i` initially zero and two zero elements, Go’s `i, values[i] = 1, 7` left `values[0]` equal to `7`. Compiled C returned `0`. The writer saves the right-hand values, then evaluates each destination during the stores. Capture destination operands before the first store, including for tuple results. [adapters/c/src/write.rs:2496](https://github.com/beyond10x/codespec/blob/91086c62d67611808206a935e8e5857e94cdc0e6/adapters/c/src/write.rs#L2496) · [adapters/c/src/write.rs:2515](https://github.com/beyond10x/codespec/blob/91086c62d67611808206a935e8e5857e94cdc0e6/adapters/c/src/write.rs#L2515)

### Translation

- **A5 · Rust parameter shadowing produces Go that fails to compile.** *Logic · observed.* A Rust function that rebinds parameter `n` with `let n = n + 5i64` read and wrote successfully.
