The same page goes by different names depending on where the reader sees it:

| page | names in use |
|---|---|
| overview | "Documentation" (navbar), "codespec" (sidebar, H1), "Overview" (footer) |
| CLI reference | "codespec CLI" (sidebar, footer), "codespec" (H1, search path), "CLI reference" (index) |
| greeter | "Showcase" (navbar), "Showcase: greeter" (sidebar, under "Examples"), "One program through codespec" (H1), "See one program go through" (home) |
| support | "Support" (navbar), "Language support" (sidebar, H1) |
| adapter guide | "Add a reader or writer adapter" (sidebar), "Add an adapter" (footer) |

Three things are called "codespec": the product, the overview and the CLI reference. Hand-written pages
open with a header card ("Start here · 3 of 4", a lede and a source line). Generated pages open with a
plain H1, set as a code chip on `cir/1` and `codespec`. The numbering starts at "2 of 4" because the
index has no card. The "Showcase" navbar item is active only on greeter, not on series.

Effect: labels the reader can't repeat or match. A search result reading "Reference › codespec" doesn't
say it is the CLI.

Fix direction (one line): one name per page used everywhere, the CLI page's H1 "codespec CLI", and one
header style for every page. H1s of generated pages land in `crates/docs/src/cli.rs`, `cir.rs`,
`showcase.rs` and `netcheck.rs`.

Severity S3: costs recognition, blocks nothing.
