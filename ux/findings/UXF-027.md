Status says it describes release 0.6.1 and that shipped means code in the release. It lists the C
reader and the C writer as shipped. Neither is in 0.6.1: the C adapters came after the tag and are
under "Unreleased" in the changelog. The home page's meta line and the overview name the C writer
too, but they say "this tree".

The archive contents are stated on two pages and differ. Getting started says an archive holds the
Go and Rust readers and writers, which is true of 0.6.1. Add a reader or writer adapter says each
release's archive also holds the C writer and its runner.

Effect: a reader who installs 0.6.1 from Getting started and asks for the C reader or writer finds
no `codespec-read-c` or `codespec-write-c` in the archive, for a capability Status calls shipped.

Fix direction (one line): mark the C entries as in this tree, not in the release, until a release
carries them, and state the archive contents on Getting started only, linked from the adapter guide.

Severity S2: a wrong statement about what the installed release can do, on the page meant to settle
that question.

Fixed in R-07: Status says it describes this tree, names 0.6.1 as the last release and points to the changelog's Unreleased section for what the tree adds, the C reader and writer among them; "shipped" means code in this tree. The archive contents are on Getting started § Install only; Add a reader or writer adapter links there. Its removed list (the C writer and `codespec-run-c` in each archive) is true of the release workflow in this tree, `.github/workflows/release-build.yml`, not of 0.6.1. The C entries stay "shipped": the status vocabulary (`b10x-status/1`) has no "in the tree, not released" value.
