A first-time reader is told different things about what exists, depending on the page:

- Release: the home eyebrow, the home status heading and the Status page say 0.1.2. The getting-started
  output shows `codespec 0.1.2`. The crates page, the CLI and the status data say 0.6.0. The Vision
  page says `series` was "done in 0.2.0".
- State: on the home page the KPI row says 0 decided and 0 planned. The feature cards directly below it
  mark the Rust reader "decided" and the algorithmic example "planned". Vision and Status say both have
  shipped.
- Languages: the docs index says "This tree reads Go and Rust". Getting started says the release holds
  "the three adapters" and "There is no Java reader". The Language support page and the status data list
  Java and Groovy readers.

Effect: the reader can't trust the pages that a first visit goes through: home, docs index, Getting
started, Status.

Fix direction (one line): bring product.json and the four Start-here pages up to 0.6.0 and the current
adapters, and add a check so they cannot drift again. `status.mdx` counts as generated (line 6 names
`codespec-docs`), so its version lands in `crates/docs/src/status.rs`, which already holds 0.6.0.

Severity S2: no task is blocked, but the main facts are wrong on the first pages a reader opens.

Fixed in R-03: product.json and status.mdx name no release (status.mdx reads status.version); getting-started pastes `codespec 0.6.0`, lists the ten adapters and uses Python for the missing-adapter case; the docs index lists the Java and Groovy readers; the two stale feature cards are shipped.
