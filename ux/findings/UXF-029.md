R-06 raised inline code in tables from 12.7 px to 14 px (UXF-024). Code does not wrap inside a
word, so tables whose cells hold long identifiers or types grew wider than the text column. At the
gating viewports three more tables scroll sideways than in R-06, and two that already did grew by
about 90 px. The support matrix (UXF-021) is not counted here.

Effect: on Readers, passes and writers, the codespec CLI, Crates, Static analysis and netcheck the
reader scrolls a table sideways to read its last column; nothing on screen says it is cut except a
fade.

Fix direction (one line): let code in table cells break at `::`, `.` and `_` (or `overflow-wrap:
anywhere`) in `website/src/css/custom.css`, keeping 14 px.

Severity S3: content reachable, costs a sideways scroll per table.

Fixed in R-07: `website/src/css/custom.css` lets inline code in table cells break anywhere (`overflow-wrap: anywhere`) at 14 px. On the five pages no Markdown table scrolls sideways at 1366x768 or 1280x720; the support matrix is UXF-021.
