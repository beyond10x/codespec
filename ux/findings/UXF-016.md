UXF-006 closed the release numbers and one language list. Since then the C reader and C writer were
added (`adapters/c`, `adapters/c-read`). The home page, the Overview's first paragraph and its "What it
is not" list still give the old list. The Overview's own adapter table, the pipeline page, Getting
started and Language support each give a different one. Status lists none of the Java, Groovy or C
adapters as capabilities.

Effect: a reader can't tell whether codespec writes C or reads Java, and the pages that should settle
it disagree.

Fix direction (one line): state the language list once, generated from the adapter set (Status or
Language support), and link to it from the home page and the Overview.

Severity S2: a wrong statement on the first two pages a visitor reads. The R-05 notes say some
`website/data/conformance/*` files are stale from other work; the prose pages disagree regardless.

Fixed in R-05: the home page meta, the overview (its sentence, adapter row and "What it is not" item) and the pipeline adapter table name the Java and Groovy readers and the C reader and writer; the C reader is listed as written in Rust. Status gains "C reader conforms to the kit" and "C writer conforms to the kit" (`crates/docs/src/status.rs`). The test reads the readers and writers from `website/data/support-matrix.json`.
