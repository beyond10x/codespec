The page names the archive's contents in one place, as checklist line 1 asks, but the list is
short by the C writer, the evaluator writer and the C and evaluator runners, and it is silent on the
C reader (not in the archive, unlike Java and Groovy it is not named as missing either). A reader
who wants the C writer cannot tell from the install page that the download has it.

Effect: a reader wanting C output may build from source for an adapter the archive already holds,
or look for the C reader in an archive that has none.

Fix direction (one line): list the archive as the workflow does, and name the C reader with the
Java and Groovy readers as built from source.

Severity S3: the install still works; the list undersells the download.
