The site ships no search: the navbar holds the title, six links, GitHub and the theme toggle, and no
search box or search button on any of the 19 pages, at either gating viewport, in either theme. The
adapter lists search as always visible, so gate 2 fails on every page, and gate 5's "Tab reaches
search" fails with it.

Effect: a reader with a term (`codespec trace`, `TypeParam`) has to guess the page. The screen-only
user still reaches every task, through the navbar and the sidebar, at 10 actions for the two CLI tasks
(see `ux/rounds/R-01/report.md`).

Fix direction (one line): add a local search (no third-party service) to the navbar.

Severity S2: a hard gate fails on every page; no task is blocked.

## Closed in R-01

Red: with the waiver removed, `npx playwright test` failed `gate2 search:missing` and `gate5
keyboard:tab-reaches-search` on all 20 pages, 80 units each, none waived.

Fix: `@easyops-cn/docusaurus-search-local` 0.55.3 (pinned, local lunr index built with the site, no
external service, Docusaurus 3.10.2 deduplicated) as a theme in `website/docusaurus.config.ts`; its
box sits in the navbar at every viewport. Its placeholder colour is raised to 4.5:1 in
`website/src/css/custom.css` (axe `color-contrast` on the shortcut hint otherwise). The adapter
locates the box by `.navbar__search-input`; the screen-only user (§ 7.1) now uses a visible search box
when no strong link is in view: click, type the query (one action), click the best result.

Green: 0 search and keyboard failures on 21 pages; screen-only actions trace options 10 → 3, reach
reports 10 → 3, add an adapter 8 → 3, map a repository to syscalls 8 → 3. The plugin's results page
`/codespec/search` focuses its own box on load: UXF-005.
