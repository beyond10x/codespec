## Not provided

- **No network I/O or concurrency in `cir/1`.** Such code is kept as a `foreign`
  statement and refused by writers for another language.
- **No language model.** Nothing in the pipeline guesses; this is not planned.
- **No ESS integration.** Using an ESS conformance suite as an equivalence oracle is a direction
  in the [Vision](/docs/vision#later), not a plan.

## Known limitations

- **The Rust reader reads a subset.** One file, `src/lib.rs`; no generics, traits other than
  `Display`, closures, `while` or `loop`, `?`, or integer literals nothing types. Each is kept as a
  `foreign` statement with a refusal inside a body; an item outside it (a generic function, a trait
  impl) is listed as a refusal and left out. Go's `int` and `int64` both come back from Rust as `int64`.
- **The harness speaks two programs.** Its trace generators are the `orders` and `inventory`
  examples' (`trace` in `harness.toml`); `greeter` is checked by equality with its checked-in
  outputs and its builds.
- **The Rust writer refuses more than the Go writer.** It refuses a function holding a `foreign`
  statement, a loop over a map the facts do not list, an `error` result that is not `fallible`, and
  a write into a map entry's value (`m[k]++`); each lands in `refusals.json`.
- **Single-threaded Rust output.** Shared values are `Rc<RefCell<T>>` and channels of `any` are
  `std::sync::mpsc::Sender<Message>` drained by the caller.
