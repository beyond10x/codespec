# The cir/1 model

`cir/1` is the format at the centre of codespec: one JSON document per source module (a Go
package today). The Rust types in
[`crates/model/src/lib.rs`](https://github.com/beyond10x/codespec/blob/main/crates/model/src/lib.rs)
are its only definition. `codespec schema` prints the JSON Schema generated from them, checked in
as `schemas/cir-1.schema.json`; a test fails when the two differ. Every object, kind and field is
listed in the generated [cir/1 reference](/docs/reference/cir-1).

## What a document holds

| Level | Nodes |
|---|---|
| module | `name`, `reader` (`language`, `name`, `version`), `doc`, `types`, `consts`, `errors` (sentinel errors), `funcs`, `layout`, `facts`, `refusals` |
| types | `int` (`width`: `platform`, 8, 16, 32, 64; `signed`), `bool`, `string`, `error`, `any`, `unit`, `named`, `ptr`, `slice`, `map`, `chan` (`dir`), `tuple` |
| declarations | `struct`, `newtype`, `enum`, `union` |
| statements | `let`, `var`, `assign`, `incr`, `decr`, `if`, `for_range`, `switch`, `return`, `expr`, `send`, `lookup_else`, `foreign` |
| expressions | `lit`, `nil`, `var`, `const`, `errvar`, `field`, `index`, `call`, `method`, `binop`, `unop`, `struct`, `conv`, `make`, `zero`, `intrinsic`, `to_error` |

Every node with variants is tagged by the field `k`. The diagram below is the `greeter` example
after `codespec pass`, generated by `codespec-docs` from the checked-in document (the whole run is
on the [showcase](/docs/examples/greeter)):

## Design choices

| Choice | Why |
|---|---|
| The Rust model is the definition; the schema is generated | one source of truth |
| `reader` provenance on every module | a document says what produced it |
| `int` has `width` and `signed`; `platform` is the source's machine word | no width that only one language understands |
| `pos` (`file:line`) on every statement and declaration | refusals and diffs point at the source |
| every expression has a type, and it is required | writers never infer a type |
| `union` and `switch` | Rust enums with data, Go `switch`, Rust `match` |
| ordered lists only, no maps | the encoding is canonical |
| `layout` keeps the source's declaration order | a writer that keeps order can |

## Reading is strict

`Module::from_json` refuses an unknown field anywhere, an unknown kind, an expression without a
type, and any `format` other than `cir/1`. `codespec validate --canonical` also refuses a document
whose bytes are not its canonical encoding. Run next to a copy of `orders.read.cir.json`, with
`target/debug` on `PATH`:

```shell-session
$ jq -c '.format="cir/2"' orders.read.cir.json > v2.json
$ codespec validate v2.json
codespec: v2.json: format is "cir/2", this reader reads "cir/1"
$ jq -c . orders.read.cir.json > compact.json
$ codespec validate --canonical compact.json
codespec: compact.json: valid, but not in canonical encoding
```

Both exit 1. An unknown field is refused with the list of fields the object has; the
[adapter guide](/docs/guides/add-an-adapter#the-boundary-is-checked) shows one.

Do not loosen reading to admit a tool's output: fix the tool. A change in meaning, identity, field
names or canonical encoding is a new format version, `cir/2`, never an edit to `cir/1`.

## What cir/1 cannot express

A construct with no node (in the Go reader: a goroutine, `defer`, an `if` with an init statement,
named results, an expression it has no node for) is kept as a `foreign` statement with its source
text, its language and a reason, and the
module lists it under `refusals`. Nothing is dropped or approximated. A writer for the same
language can splice the source back; a writer for another language refuses the function that holds
it. See [Readers, passes and writers](/docs/concepts/pipeline#refusals).

## Facts

`facts` is absent when a reader writes a module. `codespec pass` fills it with whole-module results
that writers read instead of deciding for themselves; a writer that needs them (Rust) refuses a
module without them. See [passes and facts](/docs/concepts/pipeline#passes-and-facts).
