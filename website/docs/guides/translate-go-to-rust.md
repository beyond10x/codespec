# Translate a Go package to Rust

This guide translates a small Go package that is not one of the repository's examples. Every
command was run from the repository root after `task build` ([Getting started](/docs/getting-started));
absolute paths are shortened to `<checkout>`.

## 1. The package

`work/stock/stock.go`, one Go package in its own directory:

```go title="work/stock/stock.go"
// Package stock counts items on shelves.
package stock

import (
	"errors"
	"fmt"
)

type SKU string

type Item struct {
	SKU   SKU
	Count int64
}

var ErrNotPositive = errors.New("quantity must be positive")

type Store struct {
	items map[SKU]*Item
}

func New() *Store {
	return &Store{items: map[SKU]*Item{}}
}

func (s *Store) Add(sku SKU, n int64) error {
	if n <= 0 {
		return ErrNotPositive
	}
	it, ok := s.items[sku]
	if !ok {
		s.items[sku] = &Item{SKU: sku, Count: n}
		return nil
	}
	it.Count += n
	return nil
}

func (s *Store) Take(sku SKU, n int64) error {
	it, ok := s.items[sku]
	if !ok {
		return fmt.Errorf("no item %s", sku)
	}
	if it.Count < n {
		return fmt.Errorf("only %d of %s", it.Count, sku)
	}
	it.Count -= n
	return nil
}

func (s *Store) Count(sku SKU) (int64, bool) {
	it, ok := s.items[sku]
	if !ok {
		return 0, false
	}
	return it.Count, true
}
```

The Go reader type-checks the package with `go/types`, so it must compile on its own:

```shell-session
$ cd work && go mod init example.com/stock

go: to add module requirements and sums:
	go mod tidy
$ cd work && go vet ./stock
```

## 2. Read it into cir/1

```shell-session
$ export CODESPEC_ADAPTERS=target/adapters
$ target/debug/codespec read --lang go work/stock --out work/stock.read.cir.json
$ target/debug/codespec validate --canonical work/stock.read.cir.json
work/stock.read.cir.json: cir/1 stock, 3 types, 4 funcs, 0 refusals
```

No refusals: everything in the package has a `cir/1` node. A package with a goroutine, `defer` or
another construct `cir/1` cannot express would list it here
([Refusals](/docs/concepts/pipeline#refusals)).

## 3. Apply the passes

The Rust writer refuses a module without facts, and writes nothing:

```shell-session
$ target/debug/codespec write --lang rust work/stock.read.cir.json --out work/no-facts
codespec-write-rust: module stock has no facts: the `facts` pass has not run; run `codespec pass` over it first
codespec: target/adapters/codespec-write-rust exited with exit status: 1
$ test -e work/no-facts || echo 'nothing written'
nothing written
```

So pass it first:

```shell-session
$ target/debug/codespec pass work/stock.read.cir.json --out work/stock.cir.json
$ jq -c .facts work/stock.cir.json
{"shared":["Item"],"comma_ok":["Store.Count"],"fallible":["Store.Add","Store.Take"],"read_only":["Store.Take","Store.Count"],"displays":["SKU"]}
```

Each fact decides one Rust mapping: `Item` is stored by pointer in a map, so it is `shared` and
becomes `Rc<RefCell<Item>>`; `Add` and `Take` are `fallible` and return `Result<(), Error>`;
`Count` is `comma_ok` and returns `Option<i64>`. `Take` writes only through the shared item, not
the store, so it is `read_only` and takes `&self`; `Add` inserts into the store's map and takes
`&mut self`.

## 4. Write the Rust crate

```shell-session
$ target/debug/codespec write --lang rust work/stock.cir.json --out work/stock-rs
$ cat work/stock-rs/refusals.json
[]
$ cat work/stock-rs/src/lib.rs
```

```rust title="work/stock-rs/src/lib.rs"
    pub sku: SKU,
    pub count: i64,
}
#[derive(Debug, Clone, PartialEq)]

    items: BTreeMap<SKU, Rc<RefCell<Item>>>,
}
pub fn new() -> Store {
    Store { items: BTreeMap::new() }
}
impl Store {
    pub fn add(&mut self, sku: SKU, n: i64) -> Result<(), Error> {
        if n <= 0i64 {
            return Err(Error::ErrNotPositive);
        }
        let Some(it) = self.items.get(&sku).cloned() else {
            self.items
                .insert(
                    sku.clone(),
                    Rc::new(RefCell::new(Item { sku: sku.clone(), count: n })),
                );
            return Ok(());
        };
        {
            let __value = it.borrow().count.wrapping_add(n);
            it.borrow_mut().count = __value;
        }
        Ok(())
    }
    pub fn take(&self, sku: SKU, n: i64) -> Result<(), Error> {
        let Some(it) = self.items.get(&sku).cloned() else {
            return Err(Error::Msg(format!("no item {}", sku)));
        };
        if it.borrow().count < n {
            return Err(Error::Msg(format!("only {} of {}", it.borrow().count, sku)));
        }
        {
            let __value = it.borrow().count.wrapping_sub(n);
            it.borrow_mut().count = __value;
        }
        Ok(())
    }
    pub fn count(&self, sku: SKU) -> Option<i64> {
        let Some(it) = self.items.get(&sku).cloned() else {
            return None;
        };
        Some(it.borrow().count)
    }
}
/// Every error the module produces: its sentinel errors, its error types, and
/// `Msg` for a formatted message.
#[derive(Debug, Clone, PartialEq)]
pub enum Error {
    ErrNotPositive,
    Msg(String),
}
impl fmt::Display for Error {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Error::ErrNotPositive => f.pad("quantity must be positive"),
            Error::Msg(s) => f.pad(s),
        }
    }
}

```

Both lookups became `let … else` through `lookup-guard`; `fmt.Errorf` became `Error::Msg`; the map
is a `BTreeMap`, so any iteration over it is in key order.

A test written against the Go package's behaviour, as `work/stock-rs/tests/stock.rs`:

```rust title="work/stock-rs/tests/stock.rs"
use stock::{Error, SKU};

#[test]
fn add_take_and_count_behave_like_the_go_package() {
    let mut s = stock::new();
    let apple = SKU("apple".to_owned());
    assert_eq!(s.add(apple.clone(), 0), Err(Error::ErrNotPositive));
    s.add(apple.clone(), 5).unwrap();
    s.add(apple.clone(), 2).unwrap();
    assert_eq!(s.count(apple.clone()), Some(7));
    assert_eq!(
        s.take(apple.clone(), 9).unwrap_err().to_string(),
        "only 7 of apple"
    );
    s.take(apple.clone(), 3).unwrap();
    assert_eq!(s.count(apple), Some(4));
    assert_eq!(s.count(SKU("pear".to_owned())), None);
}
```

## Proving equivalence

A hand-written test checks the cases you thought of. The [harness](/docs/concepts/harness) checks
generated traces byte for byte, but its trace generator, built into `crates/harness`, speaks only
the `orders` commands today. Comparing `stock` that way needs a Go and a Rust driver for it and a
generator for its commands in the harness crate; there is no generic one yet.
