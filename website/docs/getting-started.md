# Getting started

Every command below was run in a checkout of this repository, and its output is pasted from that
run. Absolute paths in the output are shortened to `<checkout>`.

## Install or build

A GitHub Release carries one archive per target, `codespec-<tag>-<target>.tar.gz`, for
`x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` and `aarch64-apple-darwin`, plus
`SHA256SUMS`. Each archive holds `codespec` and the three adapters side by side, so the directory
you extract it into is the `--adapters` directory. See the
[releases page](https://github.com/beyond10x/codespec/releases); the commands below build from
source instead and use `target/debug/codespec` and `target/adapters`.

To build, you need Rust (the toolchain `rust-toolchain.toml` names, 1.97), Go 1.23 or newer, and
[go-task](https://taskfile.dev). `task build` builds the `codespec` command into `target/debug/`
and every adapter into `target/adapters/`:

```shell-session
$ git clone https://github.com/beyond10x/codespec && cd codespec
$ task build
task: [build] cargo build --locked -p b10x-codespec-cli
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 7.15s
task: [adapters] mkdir -p <checkout>/target/adapters
task: [adapters] cd adapters/go && go build -o <checkout>/target/adapters/ ./cmd/...
task: [adapters] cargo build --locked -p codespec-write-rust
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 5.01s
task: [adapters] cp target/debug/codespec-write-rust <checkout>/target/adapters/
$ target/debug/codespec --version
codespec 0.1.0
```

(`Compiling …` lines omitted.) Instead of `--adapters target/adapters` on every command you can
set `CODESPEC_ADAPTERS=target/adapters`.

## Read: Go → cir/1

`examples/orders/source/orders.go` is a 137-line Go order service: place, pay, ship, cancel, get,
list pending, and an `Audit` method that starts a goroutine.

```shell-session
$ mkdir -p try
$ target/debug/codespec read --lang go examples/orders/source --out try/orders.read.cir.json --adapters target/adapters
$ target/debug/codespec validate --canonical try/orders.read.cir.json
try/orders.read.cir.json: cir/1 orders, 9 types, 9 funcs, 1 refusals
$ cmp try/orders.read.cir.json examples/orders/orders.read.cir.json
```

`codespec read` ran the adapter `codespec-read-go`, validated what it printed, and wrote the
module in canonical encoding: the same bytes as the checked-in document. The one refusal is the
goroutine:

```shell-session
$ jq -c .refusals try/orders.read.cir.json
[{"pos":"orders.go:132","what":"go func() { …","reason":"goroutine: concurrency is outside cir/1"}]
```

## Pass: cir/1 → cir/1

```shell-session
$ target/debug/codespec pass try/orders.read.cir.json --out try/orders.cir.json
$ jq .facts try/orders.cir.json
```

`lookup-guard` also rewrote every `o, ok := s.orders[id]; if !ok { return … }` into one
`lookup_else` statement. What each fact means: [Readers, passes and writers](/docs/concepts/pipeline#passes-and-facts).

## Write Go

```shell-session
$ target/debug/codespec write --lang go try/orders.read.cir.json --out try/go --adapters target/adapters
$ diff examples/orders/source/orders.go try/go/orders.go
0a1,2
> // Code generated by codespec-write-go from cir/1. DO NOT EDIT.
> 
35c37,39
< func (e ErrWrongState) Error() string { return fmt.Sprintf("order is %s", e.Status) }
---
> func (e ErrWrongState) Error() string {
> 	return fmt.Sprintf("order is %s", e.Status)
> }
43c47,49
< type OrderPaid struct{ ID OrderID }
---
> type OrderPaid struct {
> 	ID OrderID
> }
50c56,58
< type OrderCancelled struct{ ID OrderID }
---
> type OrderCancelled struct {
> 	ID OrderID
> }
```

The Go writer prints from a `go/ast` tree, so one-line bodies come out on several lines; nothing
else differs, and the `Audit` goroutine is written back verbatim from its `foreign` statement.

## Write Rust

The Rust writer needs the facts, so it reads the passed document:

```shell-session
$ target/debug/codespec write --lang rust try/orders.cir.json --out try/rust --adapters target/adapters
$ find try/rust -type f | sort
try/rust/Cargo.toml
try/rust/refusals.json
try/rust/src/lib.rs
$ cat try/rust/refusals.json
[
  {
    "name": "Service.Audit",
    "pos": "orders.go:132",
    "reason": "foreign go statement: goroutine: concurrency is outside cir/1"
  }
]
$ cargo build --manifest-path try/rust/Cargo.toml --target-dir try/build
   Compiling orders v0.0.0 (<checkout>/try/rust)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.22s
```

The crate has no dependencies and builds; `Audit` is left out and listed, every other method is
written.

## Run the harness

```shell-session
$ target/debug/codespec harness examples/orders --seeds 200 --commands 300 --build-dir target/harness
harness: 200 seeds x 300 commands, 3 implementations (original, go, rust), 79990 output lines each, byte-equal
```

The harness built the original Go, the checked-in Go output and the checked-in Rust output
(`examples/orders/harness.toml`), ran each on 200 generated traces of 300 commands, and found no
differing byte. How a difference is reported: [The harness](/docs/concepts/harness).

## When an adapter is missing

```shell-session
$ target/debug/codespec read --lang java examples/orders/source --out try/x.json --adapters target/adapters
codespec: no read adapter for "java": target/adapters/codespec-read-java does not exist
```

Exit status 1. There is no Java reader.
