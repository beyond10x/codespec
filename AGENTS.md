# AGENTS.md — codespec

The contract for changing this repository. Organization-wide rules live in `atlas/AGENTS.md`.

## What this repository owns

`cir/1`, a typed code intermediate representation of what code does inside: types, functions,
statements, expressions. Readers lift a source language into it, passes rewrite it, writers emit a
source language from it. Design: [docs/design.md](docs/design.md). For humans: [README.md](README.md) and
the site.

| path | what |
|---|---|
| `crates/model` (`b10x-codespec-model`) | the definition of `cir/1`: Rust types, strict reading, canonical JSON, the JSON Schema |
| `crates/passes` (`b10x-codespec-passes`) | the passes: `lookup-guard` and the facts writers read; rules in its crate doc |
| `crates/harness` (`b10x-codespec-harness`) | the comparison harness: trace format, generator and byte-for-byte comparison, defined in its crate doc |
| `crates/cli` (`b10x-codespec-cli`, library `codespec_cli`, binary `codespec`) | `validate`, `schema`, `read`, `pass`, `write`, `harness`; runs adapters and validates what crosses to and from them. The clap `Cli` is in `src/lib.rs` so `codespec-docs` can walk it |
| `crates/docs` (`codespec-docs`) | generates the site's derived files and checks them for drift: `generate`, `generate --check`, `provenance --site <dir> --commit <sha>` |
| `website/` | the Docusaurus documentation site, <https://beyond10x.github.io/codespec/>; the only Node in the repository |
| `schemas/cir-1.schema.json` | generated by `task schema`; drift-checked by `cargo test` |
| `adapters/<language>/` | reader and writer programs for one language, in whatever language has the best tooling for it |
| `adapters/rust-read` (`codespec-read-rust`, library `codespec_read_rust`) | the Rust reader on `syn`; what it maps, its types and its fixed table of std methods are its crate doc |
| `examples/<name>/` | a source program, the `cir/1` documents read from it and the code written from them, checked in; `harness.toml` and `drivers/` run every implementation under the harness |

## Serves

The objective of the collection this repository moves, by id from `atlas/ROADMAP.md`:

- **O2 — decisions as data, with evidence.** Code itself as typed data with one definition, and a
  translation that carries its own evidence: the original and the output run on the same inputs and
  compared byte for byte, never a claim without the run.

## Languages

- Repository tooling is Rust: the model, the CLI, passes, the comparison harness, every check.
- An adapter is written in the language whose tooling reads or writes its target best: the Go reader
  uses `go/types`, a Go writer builds `go/ast` and prints it with `go/printer`, the Rust writer and the
  Rust reader use `syn`. tree-sitter and rust-analyzer's `ra_ap_*` crates are not used
  ([docs/design.md](docs/design.md) § 7); keep dependencies minimal.
- An adapter is a program: a reader prints one `cir/1` module on stdout, a writer reads one on stdin.
  `codespec read` and `codespec write` validate every document that crosses that boundary.

## Rules for `cir/1`

- `crates/model/src/lib.rs` is the only definition. The schema, every adapter and every document
  follow it. A change to it regenerates `schemas/cir-1.schema.json` in the same commit.
- Reading is strict: unknown fields, unknown kinds, a missing type on an expression and any format
  other than `cir/1` are refused. Do not loosen this to admit an adapter's output; fix the adapter.
- A change in meaning, identity, field names or canonical encoding is a new format version (`cir/2`),
  not an edit to `cir/1`.
- Deterministic: the same source read twice gives the same bytes (`task examples-check`). Ordered
  collections only; no maps in the model.
- A construct a reader cannot express becomes a `foreign` statement holding the source text and a
  reason, plus a `refusals` entry. Never drop or approximate it.

## Gate

```console
task check
```

Needs Rust (the toolchain `rust-toolchain.toml` pins, 1.97), Go and go-task. Steps, each runnable
alone as `task <name>` (`Taskfile.yml`):

| task | what |
|---|---|
| — | `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked` |
| `adapters-check` | `gofmt -l` empty and `go vet` on `adapters/go` |
| `examples-check` | every example read twice: byte-equal, equal to its checked-in `*.read.cir.json`, canonical |
| `examples-pass` | `codespec pass` over `orders` equals `orders.cir.json` and is its own fixed point |
| `examples-go` | `orders` written as Go equals `out/go`, gofmt-clean, vetted; the Go writer's tests |
| `examples-rust` | `orders` written as Rust equals `out/rust`, exactly one refusal (`Service.Audit`), builds with `-D warnings`; a module without facts refused |
| `examples-greeter` | `greeter` passed, written as Go and as Rust, equal to the checked-in copies, no refusal, both build |
| `examples-inventory` | the Rust `inventory` crate read twice (byte-equal, equal to `inventory.read.cir.json`, no refusal), passed, written as Go and as Rust equal to the checked-in copies, all built without warnings, drivers formatted and linted, then `codespec harness examples/inventory --seeds 200 --commands 300` byte-equal |
| `examples-series` | the Go `series` package read twice (byte-equal, equal to `series.read.cir.json`, no refusal), passed, written as Go (gofmt-clean, vetted) and as Rust (no refusal, built without warnings) equal to the checked-in copies, drivers formatted and linted, then `codespec harness examples/series --seeds 200 --commands 300` byte-equal |
| `harness` | the drivers formatted and linted, then `codespec harness examples/orders --seeds 200 --commands 300` byte-equal |
| `docs-check` | `cargo run -p codespec-docs -- generate --check`: every generated file current, no raw admonition title |

Not in the gate: the site build, `task docs-site` (`npm --prefix website ci --allow-git=root &&
npm --prefix website run build`; npm 12 needs `--allow-git=root` for the Git-pinned
`@beyond10x/docs-system`, CI's Node 22 does not). Run it when a page, `product.json` or the site
config changes. CI runs it in `.github/workflows/pages.yml`.

## Generated files

Never edit these by hand; change the generator and regenerate.

| file | generator | regenerate |
|---|---|---|
| `schemas/cir-1.schema.json` | `codespec schema`, from `crates/model/src/lib.rs` | `task schema` |
| `examples/*/*.cir.json`, `examples/*/out/**` | the reader, `codespec pass` and the writers | `task examples` |
| `website/docs/reference/{cli,crates,cir-1}.md` | `codespec-docs` (`crates/docs/src/cli.rs`, `crates.rs`, `cir.rs`) | `task docs-generate` |
| `website/data/status.json` | `codespec-docs` from `CAPABILITIES` in `crates/docs/src/status.rs` | `task docs-generate` |
| `website/docs/examples/greeter.md`, `website/data/greeter-code-pair.json`, `website/static/img/greeter-cir.svg` | `codespec-docs` (`showcase.rs`, `diagram.rs`) from `examples/greeter` | `task docs-generate` |

A change to the CLI, a crate's `description`, the model, an example or the capability list is
followed by `task docs-generate` in the same commit; `docs-check` fails otherwise. A crate
`description` is public text on the site. A `shipped` capability names its check as `path::name`
(a Rust `fn`, a Go `func` or a `Taskfile.yml` task), and generation fails when it is gone; a
`planned` one names none. Planned means an epic in the planning store that is not implemented.

## Invariants and the tests that hold them

- The schema is what the model generates:
  `crates/model/tests/model.rs::the_checked_in_schema_is_the_one_the_model_generates`.
- Reading refuses unknown fields and kinds, untyped expressions and other formats:
  `crates/model/tests/model.rs::an_unknown_field_inside_a_statement_is_refused`,
  `crates/model/tests/model.rs::an_unknown_statement_kind_is_refused`,
  `crates/model/tests/model.rs::an_expression_without_a_type_is_refused`,
  `crates/model/tests/model.rs::another_format_is_refused_by_name`.
- Checked-in documents are canonical: `crates/model/tests/model.rs::every_example_document_reads_and_is_canonical`.
- Passes are idempotent: `crates/passes/tests/passes.rs::passes_run_twice_give_the_same_bytes_as_once`.
- The Go writer's output reads back to the same `cir/1`:
  `adapters/go/cmd/codespec-write-go/write_test.go::TestOrdersFixedPoint`.
- The Rust reader reads the Rust writer's `orders` output back to the passed document but for named
  exceptions:
  `adapters/rust-read/tests/reader.rs::orders_rust_output_reads_back_to_the_passed_document_but_for_named_exceptions`;
  Rust outside the subset is kept as `foreign` with a refusal at its line:
  `adapters/rust-read/tests/reader.rs::a_closure_is_kept_as_foreign_with_a_refusal_at_its_line`.
- A cir/1 `break` inside a `switch` leaves the loop in the Go output:
  `adapters/go/cmd/codespec-write-go/write_test.go::TestBreakInsideASwitchLeavesTheLoopByLabel`;
  the Go writer's `series` output reads back to the same `cir/1`:
  `adapters/go/cmd/codespec-write-go/write_test.go::TestSeriesFixedPoint`.
- The Rust writer runs a three-clause `for`'s `post` before each `continue`:
  `adapters/rust/tests/writer.rs::a_continue_in_a_three_clause_for_runs_the_post_statement_first`;
  reads every value of a multi-value assignment before it assigns any:
  `adapters/rust/tests/writer.rs::a_swap_reads_every_value_before_it_assigns_any`.
- The Rust writer refuses a module without facts:
  `adapters/rust/tests/writer.rs::a_module_without_facts_is_refused_naming_the_pass`; its crate builds
  without warnings: `adapters/rust/tests/writer.rs::the_written_crate_builds_without_warnings`.
- The harness catches a one-token change:
  `crates/cli/tests/harness.rs::a_planted_one_token_change_in_the_rust_output_fails_with_seed_rust_and_first_line`;
  traces are platform-independent: `crates/harness/tests/harness.rs::a_trace_is_pinned_across_platforms`.
- Generated site files are current: `crates/docs/src/main.rs::every_generated_file_is_current_in_this_tree`;
  every shipped capability rests on an existing check:
  `crates/docs/src/status.rs::every_shipped_capability_rests_on_a_test_that_exists`.

## Builds and worktrees

Work in a managed worktree (`worktree` CLI); never in the primary checkout. Rust builds use
`CARGO_PROFILE_DEV_DEBUG=line-tables-only CARGO_INCREMENTAL=0` (the Taskfile sets both) and the
worktree's own `target/`; never a `CARGO_TARGET_DIR` shared with another tree. Scratch output goes
under `target/`. End a merged tree with `worktree finish --discard-cache --archive <tree>`.

## Delivery

All commits and pushes are `b10x-bot[bot]` through `b10x-gates bot --repository beyond10x/codespec`;
every other GitHub write (pull request, release, re-run, dispatch) goes through `b10x-gates api`.
Common Gates run in `.github/workflows/shared-gates.yml`, `task check` in
`.github/workflows/check.yml`. Planning lives in `.engineering/planning/` (AEP).

The site: `.github/workflows/pages.yml` ("Documentation validation") builds it on every push and
pull request, runs `cargo test -p codespec-docs`, binds the build to its commit with
`codespec-docs provenance --site website/build --commit "$GITHUB_SHA"`, and on a push to `main`
uploads `website/build` as `b10x-project-site`. `.github/workflows/b10x-docs-site.yml`
("Documentation site") then deploys it through Website's reusable `project-site.yml`, for bot pushes
to `main` only.

## Release

1. Bump `version` in `[workspace.package]` of `Cargo.toml` and `const version` in
   `adapters/go/cmd/codespec-read-go/main.go` (it is written into every document as
   `reader.version`), then `task examples` and `task docs-generate` (`VERSION` in
   `crates/docs/src/status.rs` follows the workspace version, a test checks it). Move the
   `CHANGELOG.md` entries under a `## <version>` heading. `task check` green on that commit; let
   `cargo build` update `Cargo.lock`, never `cargo generate-lockfile`.
2. Annotated tag `0.x.y` on `main`, pushed as the bot.
3. `.github/workflows/release-build.yml` runs on the tag (contents: read): it builds `codespec`,
   `codespec-write-rust` and `codespec-read-rust` (Rust) and `codespec-read-go` and `codespec-write-go` (Go) for
   `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` and `aarch64-apple-darwin`, smoke-tests
   each, and uploads the artifact `codespec-<tag>-release`: the three archives
   `codespec-<tag>-<target>.tar.gz` and `SHA256SUMS`.
4. Download the artifact `codespec-<tag>-release` (`gh run download <run> -n codespec-<tag>-release`,
   read-only) and run
   `sha256sum -c SHA256SUMS`.
5. Create the GitHub Release as `b10x-bot[bot]`: copy the archives, `SHA256SUMS` and the notes under
   `target/release-assets/` and run `b10x-gates gh -- release create <tag> --verify-tag --notes-file …` from
   the checkout with paths relative to it; Gates refuses an argument holding a home-directory path.
6. Report released only after the release, its assets and their checksums are verified.

## Never

- Never loosen strict reading, or hand-edit a generated file, to make something pass.
- Never write a `cir/1` change in meaning, field names or encoding as an edit to `cir/1`; that is
  `cir/2`.
- Never hand-edit an example's outputs; if a writer refuses, change the example's source or the
  writer.
- Never commit Python or any other running code outside Rust, the adapters' own languages and the
  site build.
- Never push, tag or write to GitHub as a person: the bot only.
- Never put private names, home paths or planning ids in a crate `description`, a page or
  `product.json`: they are public.
